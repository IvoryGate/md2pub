# 颜色设计：从「配一组好看的颜色」到「建立一套阅读环境」

> 颜色在排版工具里不是皮肤。它决定了正文是否耐读、强调是否成立、暗色是否真的可用。这篇文档解释 md2pub 的配色模型与约束。

## 0. 先定角色，再挑颜色

大多数配色失败，不是颜色本身难看，而是**角色混乱**：强调色被用来写正文，标题和正文的明度差不够，引用块的底色和纸色几乎一样。

md2pub 的调色板只有九个角色：

| 角色 | 用途 | 约束 |
| --- | --- | --- |
| `bg` | 纸色 / 页面底色 | 高明度、极低彩度，不能是纯白 |
| `text` | 正文 | 与纸色对比 ≥ 7:1 |
| `heading` | 标题 | 比正文更深，对比 ≥ 9:1 |
| `accent` | 强调、页码、标签、标题装饰 | 与纸色对比 ≥ 3:1 |
| `muted` | 次要信息、注释、占位 | 对比 ≥ 3.2:1 |
| `strong` | 行内加粗 | 在强调色族内，更深更饱和，对比 ≥ 4.5:1 |
| `italic` | 行内斜体 | 取方案次色，承担色相变化，对比 ≥ 3:1 |
| `quoteBg` | 引用块底色 | 接近纸色，但可辨识 |
| `codeBg` / `codeFg` | 代码块 | 深浅反转，保证代码可读 |

先接受这个约束：**一个调色板里，真正有彩色相位的只有强调色与斜体**。其余颜色都在低彩度的墨色轴上。这样读者不会在正文里被颜色打断。

## 1. 为什么用 OKLCH，而不是 HSL 或手动 HEX

HSL 的「亮度」不是感知亮度。把黄色和蓝色的 `L` 都设成 50%，黄色看起来会亮得多；同样明度的红和绿，视觉重量也不一样。结果就是：换一个色相，整个版面的明暗关系就塌了。

OKLCH 把颜色拆成三个更接近视觉感知的维度：

- **L（Lightness）**：0–1，感知明度；
- **C（Chroma）**：彩度，0 是灰；
- **H（Hue）**：色相角，0–360。

在 OKLCH 里，保持 `L` 不变、只旋转 `H`，颜色会保持接近的视觉重量。这正是「换主题色但版面不变脏」的关键。

```css
/* 同一明度，只换色相 */
color: oklch(0.62 0.18 25);   /* 红 */
color: oklch(0.62 0.18 145);  /* 绿 */
```

md2pub 内部用 `hexToOklch` / `oklchToHex` 做转换，再输出浏览器可直接使用的 HEX。这样导出的图片和界面显示一致，不依赖浏览器对 `oklch()` 的支持差异。

## 2. 从一颗种子色推导整套色板

用户只需要选一个种子色（或一个古典色预设），系统按固定链路生成整套色板：

```text
种子色
  → 固定色相关系（单色 / 邻近 / 互补 / 分裂 / 三等分）
  → 收敛明度与彩度到可用区间
  → 生成纸色、墨色层级、强调色、引用/代码底色
  → 逐项做 WCAG 对比度校正
```

色相关系不是随便定的，每种关系对应一种「情绪强度」：

| 方案 | 次色偏移 | 第三色偏移 | 适合 |
| --- | --- | --- | --- |
| `mono` 单色 | 0° | 0° | 极简、报告、长文 |
| `analogous` 邻近 | +30° | −18° | 温和、杂志、生活方式 |
| `complement` 互补 | 180° | 0° | 强对比、观点文、品牌 |
| `split` 分裂互补 | 150° | 210° | 有张力但不刺眼 |
| `triadic` 三等分 | 120° | 240° | 活泼、插画、活动 |

默认「素笺」用互补方案：主色是玫红，次色转到 180° 附近，用在斜体和少量装饰上；第三色仍留在主色族，避免第三种颜色抢戏。

## 3. 明度建层级，彩度做反向补偿

这是整套配色的核心原则：**越深的颜色，彩度可以略高；越浅的颜色，彩度必须更低。**

原因很直接：深色面积大时，高彩度会显得厚重、廉价；浅色底如果带明显彩度，会像「没调干净的灰」。所以：

- 纸色 `bg`：`L ≈ 0.977`，`C ≈ 0.009–0.013`，只保留一点点温度；
- 标题 `heading`：`L ≈ 0.20`，接近黑，但保留极低彩度，避免死黑；
- 正文 `text`：`L ≈ 0.30`，比标题浅一档；
- 次要 `muted`：`L ≈ 0.56`，承担注释与占位；
- 强调 `accent`：`L` 收敛到 0.54–0.66，`C` 收敛到 0.14–0.23。

强调色的明度区间是刻意收窄的。太深，会在纸色上变成「第二层标题」；太浅，又会失去强调功能。0.54–0.66 是在米白纸上既能站稳、又不抢正文的窗口。

## 4. 对比度不是建议，是硬约束

正文能不能读，最终由对比度决定。WCAG 2.2 的阈值是：

- 正文（小字）：≥ 4.5:1；
- 大字（约 24 px 以上，或 19 px 粗体）：≥ 3:1；
- 非文本图形（图标、边框）：≥ 3:1。

md2pub 把标准再抬高一点，并把「校正」写进了生成流程：

| 角色 | 目标对比度 | 处理 |
| --- | --- | --- |
| `text` | ≥ 7:1 | 不足则继续压暗，直到达标 |
| `heading` | ≥ 9:1 | 同上 |
| `muted` | ≥ 3.2:1 | 不足则提高明度对比 |
| `accent` | ≥ 3:1 | 不足则向深/浅两端调整 |
| `strong` | ≥ 4.5:1 | 在强调色族内调整 |
| `italic` | ≥ 3:1 | 在次色相位上调整 |

对应实现是 `ensureContrast(fg, bg, ratio, direction)`：沿着明度轴逐步调整，直到达到目标比值。这样即使用户把种子色设成很浅的黄色，正文也不会变成不可读的浅灰。

> 对比度是底线，不是审美。先保证能读，再谈「高级感」。

## 5. 纸色：为什么不是 #fff

纯白底在屏幕上会显得「发蓝、发空」，尤其是大面积阅读时。md2pub 的纸色有两个方向：

- 暖纸（warm）：色相约 85°，极低彩度，接近米白，适合长文、杂志、古典主题；
- 冷纸（cool）：色相约 250°，极低彩度，接近雾白，适合科技、工具、暗色过渡。

纸色的明度固定在 0.977 附近，不随种子色变化。种子色只影响强调色和墨色的色相偏移，不改变纸的「白」。这是为了让切换主题时，阅读环境的亮度保持稳定。

## 6. 古典色：低饱和的长期主义

内置的九组古典色，选择标准不是「像古画」，而是**低饱和、耐看、和米白纸相处不脏**：

| 名称 | 种子色 | 方案 | 纸色 |
| --- | --- | --- | --- |
| 清爽·玫 | `#ff2e4d` | 互补 | 暖 |
| 胭脂 | `#9d2933` | 互补 | 暖 |
| 朱砂 | `#ff461f` | 互补 | 暖 |
| 绛紫 | `#8c4356` | 邻近 | 暖 |
| 竹青 | `#789262` | 邻近 | 暖 |
| 黛蓝 | `#425066` | 互补 | 冷 |
| 秋香 | `#d9b611` | 分裂 | 暖 |
| 茶色 | `#b35c44` | 单色 | 暖 |
| 松花 | `#bce672` | 分裂 | 暖 |

它们的共同点是彩度不高。高饱和的传统色（正红、明黄）在屏幕上面积稍大就会刺眼，只适合做小面积点缀；而卡片里的强调色会出现在标题装饰、页码、标签等多个位置，必须经得起反复看。

## 7. 暗色不是把亮色反过来

暗色主题的常见错误是「亮色板整体反相」：纸色变黑、文字变白，但强调色仍然是原来那个高饱和红，结果在暗底上发光、刺眼。

md2pub 的暗色模式重新取了一组值：

- 纸色 `L ≈ 0.17`，不是纯黑；纯黑会让文字边缘产生光晕；
- 正文 `L ≈ 0.88`，不用纯白；
- 标题 `L ≈ 0.97`；
- 强调色 `L` 提到 0.60–0.74，彩度略降，避免在暗底上「跳出来」；
- 次要文字仍需 ≥ 3.2:1，不能因为「暗色可以低对比」就放弃可读性。

暗色不是另一种风格，而是同一套层级关系在低亮度环境下的重新求解。

## 8. 调色流程

面板里的顺序不是随意的，它对应一条决策链：

1. **选种子**：先定「这篇内容的气质」，不要先调纸色；
2. **选方案**：决定次色偏离多少度，也就是「要不要第二种情绪」；
3. **选纸色**：暖 / 冷，决定阅读环境的温度；
4. **选明暗**：亮色 / 暗色；
5. **检查对比度**：面板会显示正文、强调、次要文字的实测比值；
6. **微调**：只动种子色，不要逐项改九个角色——手改会破坏角色之间的一致性。

## 9. 颜色检查表

- [ ] 正文对比度是否 ≥ 7:1？
- [ ] 强调色是否只出现在该强调的地方？
- [ ] 标题与正文是否有明确的明度差，而不是只差字号？
- [ ] 引用块底色是否能被识别，但不抢正文？
- [ ] 暗色模式下，强调色是否仍然刺眼？
- [ ] 打印成灰度后，层级是否还成立？

最后一条经常被忽略：把界面转成灰度，如果标题、正文、注释仍然能分出三层，说明明度关系是成立的；如果全靠色相区分，灰度下就会糊成一片。
