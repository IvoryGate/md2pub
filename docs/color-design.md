# 颜色设计：从「配一组好看的颜色」到「建立一套阅读环境」

> 颜色在排版工具里不是皮肤。它决定了正文是否耐读、强调是否成立、暗色是否真的可用。这篇文档解释 md2pub 的配色模型与约束。

## 0. 先定角色，再挑颜色

大多数配色失败，不是颜色本身难看，而是**角色混乱**：强调色被用来写正文，标题和正文的明度差不够，引用块的底色和纸色几乎一样。

md2pub 的调色板有十二个角色：

| 角色 | 用途 | 约束 |
| --- | --- | --- |
| `bg` | 纸色 / 页面底色 | 高明度、极低彩度，不能是纯白 |
| `text` | 正文 | 与纸色对比 ≥ 7:1 |
| `heading` | 标题 | 比正文更深，对比 ≥ 9:1 |
| `accent` | 主色：强调、页码、标签、标题装饰 | 与纸色对比 ≥ 3:1 |
| `accent2` | 第二色：引用边框、双子塔第二笔、列表标记 | 与纸色对比 ≥ 3:1 |
| `accent3` | 第三色：表头等辅助装饰 | 与纸色对比 ≥ 3:1 |
| `muted` | 次要信息、注释、占位 | 对比 ≥ 3.2:1 |
| `strong` | 行内加粗 | 在强调色族内，更深更饱和，对比 ≥ 4.5:1 |
| `italic` | 行内斜体 | 取方案次色，承担色相变化，对比 ≥ 3:1 |
| `quoteBg` | 引用块底色 | 接近纸色，但可辨识 |
| `codeBg` / `codeFg` | 代码块 | 深浅反转，保证代码可读 |

主色、第二色、第三色各自承担明确的落点：引用/双线/列表用第二色，表头用第三色，正文仍留在低彩度墨色轴上。颜色有分工，读者才不会被颜色打断。

## 1. 为什么用 OKLCH，而不是 HSL 或手动 HEX

HSL 的「亮度」不是感知亮度。把黄色和蓝色的 `L` 都设成 50%，黄色看起来会亮得多；同样明度的红和绿，视觉重量也不一样。结果就是：换一个色相，整个版面的明暗关系就塌了。

OKLCH 把颜色拆成三个更接近视觉感知的维度：

- **L（Lightness）**：0–1，感知明度；
- **C（Chroma）**：彩度，0 是灰；
- **H（Hue）**：色相角，0–360。

在 OKLCH 里，保持 `L` 不变、只旋转 `H`，颜色会保持接近的视觉重量。这正是「换主题色但版面不变脏」的关键。

```css
/* 同一明度，只换色相 */
color: oklch(0.62 0.18 25);   /* 红 */
color: oklch(0.62 0.18 145);  /* 绿 */
```

md2pub 内部用 `hexToOklch` / `oklchToHex` 做转换，再输出浏览器可直接使用的 HEX。这样导出的图片和界面显示一致，不依赖浏览器对 `oklch()` 的支持差异。

## 2. 从一颗种子色推导整套色板

用户只需要选一个种子色（或一个方案预设），系统按固定链路生成整套色板：

```text
种子色
  → 色相关系（单色 / 相似 / 邻近 / 互补 / 分裂 / 三角 / 四角）
  → 每个色族生成浅—深 5 阶
  → 生成纸色、墨色层级、主色/第二色/第三色、引用/代码底色
  → 逐项做 WCAG 对比度校正
```

色相关系不是随便定的，每种关系对应一种「情绪强度」：

| 方案 | 色相偏移 | 气质 |
| --- | --- | --- |
| `mono` 单色 | 0° | 同一色相，用明度/彩度分层；极简、长文 |
| `analogous` 相似 | ±30° | 柔和、统一；生活方式、杂志 |
| `neighbor` 邻近 | ±60° | 比相似更有变化；观点、叙事 |
| `complement` 互补 | 180° | 冷暖对比最强；观点文、品牌 |
| `split` 分裂 | 150° / 210° | 互补的柔化版；有张力但不刺眼 |
| `triadic` 三角 | 120° / 240° | 三种性格；插画、活动 |
| `tetrad` 四角 | 70° / 180° / 250° | 四色组，接近 Paletton 的 Tetrad |

默认「素笺」保留原来的互补方案与米白纸：主色是玫红，次色转到 180° 附近；这个默认不强制套用新方案，用户切到其他配色时才会替换整套色板。

**四色组怎么落到卡片上**：一个色族（family）会给深浅 5 阶；卡片只取其中稳定的几档——主色做标签与标题装饰，第二色做引用边框、双子塔第二笔与列表标记，第三色做表头，强调色做加粗。色族不是装饰画，而是有明确职责的一套颜色。

## 3. 明度建层级，彩度做反向补偿

这是整套配色的核心原则：**越深的颜色，彩度可以略高；越浅的颜色，彩度必须更低。**

原因很直接：深色面积大时，高彩度会显得厚重、廉价；浅色底如果带明显彩度，会像「没调干净的灰」。所以：

- 纸色 `bg`：`L ≈ 0.977`，`C ≈ 0.009–0.013`，只保留一点点温度；
- 标题 `heading`：`L ≈ 0.20`，接近黑，但保留极低彩度，避免死黑；
- 正文 `text`：`L ≈ 0.30`，比标题浅一档；
- 次要 `muted`：`L ≈ 0.56`，承担注释与占位；
- 主色 `accent`：`L` 收敛到 0.56–0.62，`C` 收敛到 0.16–0.28；
- 第二色 / 第三色：`L` 分别落在 0.54–0.64 / 0.46–0.56，保证在纸色上站得住，又不会和主色抢同一个明度；
- 每个色族在面板里展示 5 阶（浅→深），但卡片只取稳定的一档。

强调色的明度区间是刻意收窄的。太深，会在纸色上变成「第二层标题」；太浅，又会失去强调功能。0.56–0.62 是在米白纸上既能站稳、又不抢正文的窗口。

## 4. 对比度不是建议，是硬约束

正文能不能读，最终由对比度决定。WCAG 2.2 的阈值是：

- 正文（小字）：≥ 4.5:1；
- 大字（约 24 px 以上，或 19 px 粗体）：≥ 3:1；
- 非文本图形（图标、边框）：≥ 3:1。

md2pub 把标准再抬高一点，并把「校正」写进了生成流程：

| 角色 | 目标对比度 | 处理 |
| --- | --- | --- |
| `text` | ≥ 7:1 | 不足则继续压暗，直到达标 |
| `heading` | ≥ 9:1 | 同上 |
| `muted` | ≥ 3.2:1 | 不足则提高明度对比 |
| `accent` | ≥ 3:1 | 不足则向深/浅两端调整 |
| `accent2` / `accent3` | ≥ 3:1 | 在各自色族内调整 |
| `strong` | ≥ 4.5:1 | 在主色族内调整 |
| `italic` | ≥ 3:1 | 在次色相位上调整 |

对应实现是 `ensureContrast(fg, bg, ratio, direction)`：沿着明度轴逐步调整，直到达到目标比值。这样即使用户把种子色设成很浅的黄色，正文也不会变成不可读的浅灰。

> 对比度是底线，不是审美。先保证能读，再谈「高级感」。

## 5. 纸色：不是永远的米白

纸色是配色的一部分，不是固定的底。预设会直接把纸张染成主色相：朱砂是红纸，竹青是绿纸，黛蓝是蓝纸，夜阑是暗红纸。这样换配色时，第一眼看到的是整张卡的气质，而不是只换了一个强调色。

明度仍然受控：

- 浅色纸保持在高明度（L ≈ 0.93–0.96），保证深色文字有足够对比；
- 暗色纸压到 L ≈ 0.18，文字随之提亮；
- 墨色也带同一色相，只是彩度很低，不会变成死黑或纯灰。

默认「素笺」保留最初的米白纸；其他预设才把纸色推到对应的色调。

## 6. 配色方案：15 套完整的纸与墨

内置 15 套配色，名字只保留颜色意象；每套都直接定义纸色、墨色、主色、第二色、第三色，不再只是「一个种子色」。

| 名称 | 主色 | 纸色 | 说明 |
| --- | --- | --- | --- |
| 素笺 | 玫红 | 米白 | 默认，保留最初的清爽感 |
| 朱砂 | 正红 | 暖红纸 | 强观点、节庆 |
| 琥珀 | 橙 | 暖杏纸 | 温暖、食物、生活方式 |
| 秋香 | 黄 | 浅金纸 | 明亮、知识卡片 |
| 竹青 | 绿 | 浅绿纸 | 自然、成长、长期主义 |
| 青瓷 | 青绿 | 青白纸 | 冷静、工具、技术 |
| 黛蓝 | 蓝 | 雾蓝纸 | 理性、商务、分析 |
| 玄紫 | 紫 | 浅紫纸 | 文艺、品牌、观点 |
| 胭脂 | 玫红 | 粉纸 | 情绪、生活、美学 |
| 夜阑 | 暖红 | 暗红纸 | 夜间阅读、强氛围 |
| 深海 | 青绿 | 暗青纸 | 技术、沉浸、暗色 |
| 松烟 | 深绿 | 奶白纸 | 双色：松绿 + 陶土 |
| 霓 | 蓝紫 | 浅灰紫纸 | 三色：紫 + 珊瑚 + 青 |
| 雾蓝 | 灰蓝 | 冷白纸 | 低饱和、工具感 |
| 宣纸 | 茶棕 | 暖米纸 | 传统、纸感、长文 |

每套预设的纸张和文字都带色相，所以换配色时，卡片会明显换一张脸。彩色不再只躲在强调色里。

### 两个色轮

- **自由选色**：HEX / RGB / HSV / HSL 四种模型，配合一个可拖拽的色相环和饱和度/明度方块；先选元素（纸色、正文、标题、主色、第二色、第三色……），再改它的颜色。这里可以完全离开预设，逐项定义。
- **配色工具**：Paletton 式的关系轮。选单色 / 相似 / 邻近 / 互补 / 分裂 / 三角 / 四角，拖动轮盘定主色，用「间距」控制关系强度；每个色族会在轮上显示 浅 / 中 / 深 / 更暗 四阶，虚线连接各族的基准色。

### 色板条

除了中性色，主色、第二色、第三色各自有一条 7 阶明度条，使用同一组 OKLCH 明度阶。不同色相本身明度不同，但同一阶在黑白强度上是可比的；这比凭感觉挑色更可靠。

## 7. 暗色不是把亮色反过来

暗色主题的常见错误是「亮色板整体反相」：纸色变黑、文字变白，但强调色仍然是原来那个高饱和红，结果在暗底上发光、刺眼。

md2pub 的暗色模式重新取了一组值：

- 纸色 `L ≈ 0.17`，不是纯黑；纯黑会让文字边缘产生光晕；
- 正文 `L ≈ 0.88`，不用纯白；
- 标题 `L ≈ 0.97`；
- 强调色 `L` 提到 0.60–0.74，彩度略降，避免在暗底上「跳出来」；
- 次要文字仍需 ≥ 3.2:1，不能因为「暗色可以低对比」就放弃可读性。

暗色不是另一种风格，而是同一套层级关系在低亮度环境下的重新求解。

## 8. 调色流程

面板里的顺序不是随意的，它对应一条决策链：

1. **选种子**：先定「这篇内容的气质」，不要先调纸色；
2. **选方案**：决定次色偏离多少度，也就是「要不要第二种情绪」；
3. **选纸色**：暖 / 冷，决定阅读环境的温度；
4. **选明暗**：亮色 / 暗色；
5. **检查对比度**：面板会显示正文、强调、次要文字的实测比值；
6. **微调**：只动种子色，不要逐项改九个角色——手改会破坏角色之间的一致性。

## 9. 颜色检查表

- [ ] 正文对比度是否 ≥ 7:1？
- [ ] 强调色是否只出现在该强调的地方？
- [ ] 标题与正文是否有明确的明度差，而不是只差字号？
- [ ] 引用块底色是否能被识别，但不抢正文？
- [ ] 暗色模式下，强调色是否仍然刺眼？
- [ ] 打印成灰度后，层级是否还成立？

最后一条经常被忽略：把界面转成灰度，如果标题、正文、注释仍然能分出三层，说明明度关系是成立的；如果全靠色相区分，灰度下就会糊成一片。
