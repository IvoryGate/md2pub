# 排版设计：为什么这样设计

> 这篇文档解释 md2pub 的排版参数从哪来、为什么是这些值，以及哪些地方是刻意不做的。它不是使用说明；操作步骤见 README。

## 0. 前提：媒介变了

同一篇文章，在网页、公众号和小红书里是三件不同的事。

- 网页有滚动条、有目录、可以随时回看；
- 公众号有富文本，但样式受编辑器限制；
- 小红书是**一屏一张图**，读者靠左滑前进，没有回看路径。

最后一种约束最强，所以 md2pub 以卡片为第一目标来设计版式：**1080 × 1440**（3:4），一屏承载一个完整的阅读动作。其他比例（1:1、4:5）共享同一套排版参数，只改变可用高度与分页结果。

卡片不是网页截图。截图保留的是网页的节奏，卡片必须重新建立自己的节奏。

## 1. 版心：先定边界，再谈风格

版心（content box）是文字真正可以落笔的区域。默认值：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 页面 | 1080 × 1440 | 3:4，平台主流竖图比例 |
| 上边距 | 112 px | 给页眉标签留出呼吸位 |
| 下边距 | 124 px | 容纳页码与分页后的视觉收口 |
| 左右边距 | 88 px | 内容宽 904 px |
| 内容高 | 1204 px | 1440 − 112 − 124 |
| 版心宽高比 | 约 1:1.33 | 与整页比例接近，避免「窄长条」 |

为什么不把边距再压小？因为卡片是**整屏阅读**，不是网页的连续滚动。文字离屏幕边缘太近，阅读时眼球需要不断回扫到边界，疲劳感会明显上升。88 px 在 1080 宽里约占 8%，落在常见设计规范建议的 5%–10% 区间中部。

边距也不是四边等值：下边距比上边距多 12 px，是给页脚页码留出稳定的落点。上边距和下边距承担的功能不同，等值反而会让页码显得被挤住。

## 2. 字：字号解决「看不看得清」，行高解决「读不读得下去」

正文默认 **34 px**，行高 **1.7**，字距 **0.5 px**，段距 **22 px**。

这几个值不是拍脑袋：

- 34 px 在 1080 宽下，一行大约 24–26 个汉字。低于 30 px 时，手机缩放后正文会接近 12 px 的网页字号，阅读吃力；高于 38 px 时，一屏能容纳的信息量骤降，分页会变得零碎。
- 行高 1.7 是中文正文的舒适区。汉字是方块字，字面率高，行距太小会「糊成一片」；1.7 能在不浪费高度的前提下，给每行留出清晰的基线间隔。
- 字距 0.5 px 只做微调。中文不需要像西文那样靠字距拉开单词，过大的字距会让词组失去整体感。
- 段距 22 px 约等于 0.65 行。它小于行高，所以段落仍然是一个整体；又明显大于行内间距，读者能一眼看出「换段了」。

对应到代码，这些值在 `XhsLayout.body` 里，是纯数据：

```ts
body: {
  size: 34,
  lineRatio: 1.7,
  letterSpacing: 0.5,
  paragraphSpacing: 22,
  align: 'justify',
}
```

> 对齐方式默认是 `justify`（两端对齐）。中文没有词间空格，两端对齐不会产生西文那种「词间距忽大忽小」的问题，反而能让版心边缘更整齐。

## 3. 断行：中文需要一套专门的规则

浏览器默认的断行是「能塞就塞」，它不关心中文标点是否落在行首，也不处理行尾的视觉空洞。短句、标题、卡片这种窄栏里，问题会被放大：

- 逗号、句号跑到下一行开头；
- 行尾出现一个孤零零的字；
- 引号、括号被拆成两半；
- 每行长度参差不齐，像被狗啃过。

md2pub 的 KP 断行引擎做了四件事（算法细节见[排版算法](typesetting-algorithm.md)）：

1. **禁则**：闭合标点不起行，起始标点不悬行尾；
2. **挤压**：把全角标点自带的空白当作弹性空间，吸收行尾的小空洞；
3. **悬挂**：行末闭合标点允许半个字宽溢出，让墨迹对齐版心边缘；
4. **全局最优**：以整段为单位求最小松弛平方和，而不是逐行贪心。

结果不是「每行都一样长」，而是「每行的呼吸感一致」。这两件事在视觉上差别很大。

## 4. 层级：标题不是把字放大

标题的作用不是「更大」，而是**改变阅读速度**。读者看到标题，应该知道「可以停一下，这里换话题了」。

默认的字号阶梯以正文为基准，用比例而不是固定值：

| 层级 | 比例 | 34 px 正文下 | 作用 |
| --- | --- | --- | --- |
| H1 | 1.55× | 约 53 px | 章节开头，允许居中 |
| H2 | 1.50× | 约 51 px | 主要小节，默认左对齐 |
| H3 | 1.15× | 约 39 px | 段落群组 |
| H4 | 1.00× | 34 px | 与正文同字号，靠字重区分 |

正文改字号时，标题按比例跟随，层级不会塌；一旦手动设置标题字号，它就冻结为绝对值，不再随正文缩放。这是刻意设计的：**层级是关系，字号是决定**，两者不应该互相绑架。

标题的段前距远大于段后距（例如 H2 是 34 / 6 px，再加上段落 gap），遵循「近亲原则」：标题与它下面的内容是一组，应该靠得更近；与上一段则要拉开距离。

### 标题装饰

装饰不是必须的。默认 H1 用胶囊条、H2 用双条、H3 用三点，是为了在**远看**时也能识别层级。装饰有三种对齐约束：

- 左对齐：竖条、双条、尾点、下划线；
- 居中：下划线、胶囊、双侧线；
- 右对齐：下划线、右竖条。

切换对齐方式时，不兼容的装饰会自动替换，避免出现「胶囊挂在左边」这种结构错误。

## 5. 节奏：留白不是剩下的地方

卡片排版里，留白是主动分配的资源，不是「排完剩下的」。

- **段距** 22 px：区分段落，但不切断语义；
- **块间距** 16 px：引用、代码、表格、图片等「浮体」与上下文的额外呼吸；
- **标题段前** 34–54 px：制造章节切换的停顿；
- **页脚高度** 56 px：页码与标签的固定轨道。

这些值共同决定一屏能装多少内容，也直接进入分页算法。卡片不是「排到哪算哪」，而是先测量、再装箱；分页结果会反过来影响阅读节奏，所以版式参数和分页策略必须共享同一组数字。

## 6. 封面：海报逻辑，不是阅读逻辑

封面和正文是两种媒介：

- 正文追求**稳定**：字号、行高、边距都要可预测；
- 封面追求**一眼记住**：标题要大、留白要狠、信息要少。

所以封面有独立的标题字号（默认约 2.35× 正文，约 80 px）和独立的四边距。封面标题的换行由作者手动控制（回车即断行），而不是交给自动断行——海报上的断行是构图的一部分。

封面样式有七种（经典、竖排、巨字、杂志、书封、图封、索引），它们共享同一组文案，但重排信息层级。切换样式不应该要求重新输入内容。

**图封**把图片作为第一视觉：`overlay` 是全幅图片 + 渐暗遮罩 + 白字，适合有氛围感的照片；`separate` 是图片在上、文字在下，适合信息型封面。上传的图片会压缩到 1600px 内嵌，导出不依赖外链；外链图片需要允许跨域，否则浏览器截图会失败。

## 7. 标注：让版心变成可检查的工程对象

「参考线」不是装饰层，而是一组工程尺寸标注：

- 六条尺寸线分别标注上、下、左、右、版心宽、版心高；
- 尺寸线画在页边距里，不压内容；
- 标注文字以尺寸线中点为中心，底片不透明，线在文字后面断开；
- 导出时整层隐藏。

它解决的是一个很具体的问题：调版式时，人眼很难判断「现在到底是 88 还是 92」。把边距变成可读的数字，调整才不是盲猜。

## 8. 导出：按 1080 设计，按倍数输出

预览按 42%–84% 缩放，但排版始终按原生 1080 宽计算，导出时再按 1× / 2× / 3× 渲染。

- 1×：1080 × 1440，文件小，适合快速预览；
- 2×：2160 × 2880，默认推荐，文字边缘在手机上更干净；
- 3×：3240 × 4320，适合印刷或二次裁切，文件明显更大。

PNG 适合文字和线条，JPG 适合照片较多的版面。导出使用 `html-to-image` 在浏览器内完成，不经过服务器。

## 9. 设计检查表

发布前，可以按这个顺序检查：

- [ ] 一屏是否只有一个主要动作？
- [ ] 标题是否在提示下一步，而不是重复内容？
- [ ] 正文是否在 30–38 px 的舒适区？
- [ ] 是否有连续三行以上的「纯抽象」没有例子？
- [ ] 表格是否真的在对照，而不是把段落塞进格子？
- [ ] 图片是否在讲同一件事？
- [ ] 封面单独看，是否能在 1 秒内读出主题？

排版的目标不是「看起来专业」，而是让读者**不费力地往前走**。所有参数都应该服务于这件事；如果一个参数只是为了好看，它就不应该进入默认值。
