# 竞品分析：MD2Card vs md2pub

> 研究对象：[md2card.com](https://md2card.com/zh)（2026-10 访问）
> 方法：公开页面 + 前端 chunk 代码核对（导出菜单、分页参数、字体列表、主题商店、积分规则）。功能会持续变化，本文以研究时点为准。

## 0. 一句话结论

**MD2Card 是「内容生产 + 多端分发 + 云服务/主题市场」，md2pub 是「排版引擎 + 本地优先 + 可控设计」。**

两者都从 Markdown 出发，但商业重心不同：

- MD2Card 把「写完到发出去」的每一步都产品化：AI 总结、封面生成、公众号复制、视频、分享链接、API、主题商店。
- md2pub 把「排得好不好」做深：中文断行、全篇分页、工程标注、颜色推导、封面与页眉页脚控制。

**不建议追它的全部功能。** 真正值得借鉴的是五类能力：**分发（长图/复制/SVG/PDF）、内容入口（图片上传/封面图/模板）、视觉广度（主题/字体/背景）、页级控制（手动增删页）、以及轻量 AI 辅助**。

## 1. 定位对比

| 维度 | MD2Card | md2pub |
| --- | --- | --- |
| 目标用户 | 小红书/公众号/抖音内容创作者、知识博主、团队 | 对版式有要求的内容创作者、设计与工程背景用户 |
| 核心场景 | 快速把内容变成可发布的图/文/视频 | 把一篇长文排成一套稳定、可复现的卡片 |
| 输入 | Markdown、URL、图片、视频、AI 生成 | Markdown（含 KaTeX/Mermaid/表格/图片） |
| 输出 | PNG/SVG/JPEG、长图、HTML、PDF、Markdown、视频、公众号富文本、分享链接 | PNG/JPG（1–3×）、ZIP、目录、开发环境直写 |
| 平台 | 小红书卡片 + 公众号 + 抖音视频 | 小红书卡片（公众号规划中） |
| 商业模式 | Web 免费 + API 积分 + 主题市场 + 私有化部署 | 开源、纯前端、无账号、可自部署 |
| 技术路线 | 服务端渲染/分页 + Monaco + MDX + 主题 HTML/CSS + 云存储 | 浏览器内测量/分页 + CodeMirror + 数据驱动主题 |
| 数据 | 云端文档、分享链接、图片托管（免费版 7 天） | localStorage，本机；不上传 |

## 2. MD2Card 功能全景

### 2.1 编辑与输入

- **Monaco 编辑器**（VS Code 同款），行号、语法高亮、查找、自动换行。
- 工具栏：标题、粗体、斜体、删除线、下划线、高亮、链接、图片、代码块、引用、无序/有序列表、表格、分割线、插入空白行。
- **AI**：链接成卡 / 内容成卡（URL 抓取 → AI 总结 → 生成卡片 Markdown）。
- **大纲**显示/隐藏；`Cmd/Ctrl+S` 保存；未保存状态提示。
- **MDX 模式**：支持 MDX 语法与高级组件（设置里开关）。
- **图片上传**：可上传到图床（免费版保存 7 天）或使用本地临时链接；支持粘贴/拖拽图片。
- **贴纸**：左侧贴纸库，点击添加；粘贴本地/网络图片作为贴纸；可拖动、缩放、旋转。
- **隐藏编辑器**：进入单卡片专注预览。
- 分享：生成 `?id=` 云端链接，保存 Markdown + 主题 + 模式。

### 2.2 排版与分页

- 四种模式：**长图文 / 自动拆分 / 横线拆分 / 单张卡片不拆分**。
  - 自动拆分调用服务端 `/api/card-preview`，返回分页后的 HTML；
  - 横线拆分直接按 `<hr>` 切 HTML；
  - 长图文输出一张连续长卡。
- 自定义宽高（px）+ 尺寸预设：
  - 小红书帖子 3:4（440×586）
  - 小红书封面 3:5（540×540）
  - 手机海报 9:16（440×782）
  - 正方形 1:1（440×440）
  - A4 打印 72/96 DPI（595×842 / 794×1122）
- **页码开关**、**高度超出隐藏**、**缩放滑杆**。
- 支持**手动加页/删页**（在页面之间插入空段或删除当前页）。
- 卡片头部/尾部可双击编辑文字（主题模板的一部分）。

### 2.3 视觉与主题

- **24 个系统主题**（界面列出）：苹果备忘录、Instagram、线圈笔记本、波普艺术、字节范、阿里橙、艺术装饰、玻璃拟态、温暖柔和、简约高级灰、极简黑白、梦幻渐变、清新自然、紫色小红书、笔记本、商务简报、日本杂志、暗黑科技、复古打字机、水彩艺术、中国传统、儿童童话、赛博朋克、青野晨光。
- **主题商店**：14 个付费/免费主题，¥3–¥9；创作者分成 50% / 邀请者 20% / 平台 30%。
- **自定义主题**：本地/远程主题，CSS（可配 HTML 模板）；官方提供让 DeepSeek/Claude 生成主题 CSS 的提示词模板。
- **字体**：30+ 中文字体选择，含展示型字体（阿里普惠、钉钉进步、MiSans、思源宋体、霞鹜文楷/漫黑、得意黑、优设标题黑、斗鱼追光、汇文明朝、香萃打字机、寒蝉全圆、抖音美好体、猫啃系列、钟齐志莽行书、演示悠然小楷、站酷小薇等），另有 English 分组；支持字体搜索、字号档位（小/标准/特大）、字重。
- **背景**：无背景 / 纯色 / 渐变 / 纹理 / 图片 / 组合 / 自定义上传；纹理库很大（纸张、墙面、木纹、布料、金属、砖墙、噪点等数十种）。
- **光影/阴影**：多套预设（含无光影）。
- 每个主题可有多套**模式**（light/dark/blue/pink/mint 等配色）。

### 2.4 封面

- **front matter 驱动**：`title / description / tags / date / image / layout`。
- 两种布局：`overlay`（图片上叠字，建议竖图 440×580）、`separate`（图文分离，建议横图 440×350）。
- **封面必须包含图片**；提供模板与尺寸建议。
- 另有独立的 **「一句话封面」** 工具：输入一句描述，AI 一次生成 3 张封面。
- 封面、文字转图片都是独立入口，承担获客/引流。

### 2.5 导出与分发

- 主按钮：**导出 PNG**。
- 下拉菜单：
  - 保存为 **PNG / SVG / JPEG**
  - **复制 PNG** 到剪贴板（浏览器支持时）
  - **导出尺寸**：1× / 2× / 4×
  - 导出 **Markdown / HTML / PDF / 视频**
- **复制到公众号**：把渲染结果作为 `text/html` 写入剪贴板；公众号模式有独立主题（字节范、阿里橙、笔记本、商务简报、日本杂志）。
- **微信 API**：`/api/wechat/convert-and-draft` 可返回内联 CSS HTML，或直接上传到公众号草稿箱（需 AppID/Secret + IP 白名单）。
- **分享链接**：云端保存，登录后生成 `?id=` 链接。
- **视频**：卡片录制/图片转视频，支持解说、字幕、竖版 9:16、MP4。

### 2.6 AI 与自动化

- **URL/内容 → 总结 → 卡片**：抓取网页内容，AI 生成结构化 Markdown。
- **AI 优化视频解说**：每 100 字符消耗 1 积分。
- **图片转视频**：多场景 + 说话人 + 解说 + 字幕合成。
- **AI 生成主题 CSS**：官方提示词模板，交给大模型产出主题样式。
- **AI 封面**：一句话生成 3 张。

### 2.7 账号、开放能力与商业化

- Web 免费、无需登录即可编辑；登录后云保存/分享。
- **积分**：注册送 10；图片 1 积分起（按大小阶梯）；视频/字幕按分钟；语音按字符。
- 套餐：60 积分 ¥10、300 ¥49、1,000 ¥149、6,000 ¥599；约 ¥0.10–0.17/张；永久有效。
- **API**：`/api/generate`（Markdown → 图片 URL，腾讯 COS）、`/api/wechat/convert-and-draft`；API Key + 积分。
- **MCP Server**（npm 包）与 **Coze 插件**，可在 Cursor/VS Code/Claude 中自然语言出卡。
- **私有化部署**：Docker Compose、功能/主题定制、企业公众号风格。
- 多语言、浅/深色界面、移动端长按保存提示。

### 2.8 内容与增长

- 博客做 SEO：分栏、封面、图片尺寸、DeepSeek 工作流、API、MCP、主题 CSS。
- 免费工具矩阵：Markdown 编辑器、封面、文字转图片（20 种样式）、主题商店。
- 默认示例文档本身就是产品说明，降低首次使用门槛。

## 5. 我们明显更强的地方（要守住）

1. **中文排版是护城河**：KP 断行 + 全篇 DP，不是「CSS 排一排」。竞品的自动拆分是黑盒服务，普通用户感知不到差别，但设计/技术用户能。
2. **工程标注与参数可控**：六条尺寸线、边距/版心/页码/水印全可调，这是「排版工具」而不是「模板生成器」。
3. **封面与正文解耦**：封面文案、字号、边距独立；6 种样式；不依赖 front matter。
4. **颜色系统**：OKLCH + 对比度校正 + 古典色，比「24 套固定皮肤」更可持续。
5. **本地优先**：无账号、无上传、无锁定；数据在浏览器，导出的就是文件。
6. **文档与可解释性**：设计文档/算法文档本身就是差异化。

## 6. 我们明显更弱的地方（要补）

1. **分发链路**：没有长图、SVG/PDF、复制图片、公众号复制、分享链接。
2. **视觉广度**：3 个主题、3 种中文字体、几乎无背景/阴影；竞品是 24 主题 + 30 字体 + 数十纹理。
3. **内容入口**：没有图片上传/粘贴、没有贴纸、没有封面图、没有模板画廊。
4. **页级控制**：不能手动增删页/合并页；分页只能靠源码。
5. **AI 辅助**：没有 URL 成卡、总结、封面生成。

## 7. 可借鉴清单（按优先级）

### P0：直接影响「能不能用起来」

| 项 | 借鉴点 | 做法 | 工作量 |
| --- | --- | --- | --- |
| 长图导出（暂缓） | 更偏公众号/归档，不是小红书主链路 | 复用已导出的卡片 PNG，用 canvas 纵向拼接 | 小 |
| 复制图片 | 一键进小红书/微信 | `navigator.clipboard.write([ClipboardItem])`；失败回退下载 | 小 |
| SVG / PDF（暂缓） | 设计交付/打印，不是小红书发布必需 | html-to-image 的 `toSvg`；PDF 先做浏览器打印 | 小–中 |
| 4× 导出 | 竞品用 1/2/4× | 在导出倍数里加 4 | 极小 |
| 图片上传/粘贴 | 创作者大量用截图 | CodeMirror paste/drop → data URL/Blob URL；提示体积；导出前内联 | 中 |
| 图片尺寸语法 | `![alt|400x300]` 很实用 | 扩展解析器：alt 末尾 `|WxH`，写入 Block；渲染宽度/高度 | 小 |
| 封面图 | 小红书首图决定点击率 | `coverText.image` + `overlay/separate`；front matter 一键导入 | 中 |
| 手动页管理 | 控制滑动节奏 | 卡片间「插入分页/合并到上一页」；源码同步插入 `<!-- pagebreak -->` | 中 |
| 预设画廊 | 降低选择成本 | 用 CardPage 渲染缩略图；3 个内置 + 保存的预设；支持 JSON 导入/导出 | 中 |

### P1：提升「愿意长期用」

| 项 | 借鉴点 | 做法 |
| --- | --- | --- |
| 高亮/下划线 | `==高亮==`、`^下划线^` | markdown-it 自定义 inline rule；卡片内用强调色/下划线 |
| 分栏布局 | `:::left/right/center` | 解析为 columns block；卡片内 flex/grid；移动端堆叠 |
| 背景/阴影精选 | 竞品纹理太多，但纸感/光影有效 | 精选 6–8 种纸纹、2–3 种阴影；与纸色/主题联动 |
| 标题展示字体 | 封面需要更强的字 | 引入 6–8 款开源展示字体（得意黑、优设标题黑、站酷小薇、霞鹜漫黑等），仅标题可选，懒加载 |
| 大纲/自动保存 | 长文导航与安全感 | 侧边大纲（h1–h4）；debounce 存储 + 未保存提示 |
| 公众号复制 | 竞品的核心分发 | 先把卡片正文转成语义 HTML + 内联 CSS；复杂主题逐步适配 |
| 分享文件 | 本地优先的「分享」 | 导出 `.md2pub`（Markdown + theme + cover + settings）JSON；导入还原 |
| AI（自带 Key） | 不做云端积分，保留隐私 | 设置里填 OpenAI/DeepSeek Key；URL→MD、总结、标题建议；请求直连用户 Key |
| 移动端预览 | 小红书创作者常在手机 | 只读预览 + 长按保存；编辑仍桌面 |

### P2：战略选项，不急

- 视频导出（卡片轮播 + 配音/字幕）：工程量大、与排版工具定位偏离。
- 主题市场/分成：需要创作者供给与审核，早期不划算。
- API/MCP/Coze：等有外部调用需求再做；可先提供只读 JSON schema。
- MDX/自定义组件：维护成本高，收益低。
- 贴纸/拖拽装饰：更像「手账」而不是「排版」，会稀释品牌。

## 8. 不建议照搬的地方

1. **30+ 字体、数十种纹理**：选择过载 + 包体膨胀；我们应「少而准」。
2. **AI 视频/字幕/语音**：这是另一个产品，不是排版。
3. **积分/会员/主题商店过早商业化**：在我们还没有稳定用户前，会伤害开源/本地优先的定位。
4. **云端分享强制登录**：与「数据在本机」冲突；用文件分享替代。
5. **服务端黑盒分页**：我们的 DP 是差异化，不应退回黑盒。
6. **MDX 模式**：安全与维护成本高，且目标用户不需要。
7. **过度装饰的主题**：竞品的视觉广度是优势，但我们的差异是「克制的排版」；可以借纹理/字体，不借花哨。

---

## 9. 建议路线图（小红书优先）

> 公众号、长图、PDF、视频暂缓。当前目标不是「多平台」，而是把小红书的**封面 → 卡片组 → 发布文案 → 导出**这一条链路做到最好。

**第 1 阶段：小红书发布闭环**
1. 封面图 + 封面模板（首图决定点击率；支持 overlay / separate 两种构图）
2. 发布文案：标题（≤20 字）、正文、话题标签、@ 账号，一键复制
3. 图片组规则：最多 18 张、封面第一张、`01-cover / 02...` 命名、超限提示
4. 安全区预览：模拟小红书底部信息与右侧按钮，检查页码/水印/正文是否被挡
5. 图片上传/粘贴 + `![alt|WxH]` 尺寸语法
6. 手动增删页/合并页：控制滑动节奏，而不只依赖自动分页

**第 2 阶段：视觉与模板**
预设画廊 + 缩略图 + JSON 导入导出；精选纸纹/阴影；6–8 款标题字体；高亮/下划线；分栏；大纲/自动保存。

**第 3 阶段：增长与效率**
`.md2pub` 分享文件、自带 Key 的 AI（标题/摘要/拆卡）、移动端只读预览；公众号、长图、PDF、视频、API 均暂缓。

---

## 10. 结论

MD2Card 证明了两件事：

1. **「Markdown → 卡片」不是单点工具，而是一条内容流水线**：入口（URL/封面/文字转图片）、加工（AI/主题/分页）、出口（图/文/视频/API）都要顺。
2. **视觉模板的丰富度决定第一次点击，排版质量决定第二次使用**。

md2pub 不需要成为「更全的 MD2Card」。更合理的定位是：

> **一个本地优先、可解释、可深度控制的卡片排版工作台。**

短期把「分发」和「内容入口」补齐，中期用「主题画廊 + 字体/背景」扩大视觉吸引力，长期保持「排版引擎 + 本地数据」的差异点。不要为了追功能，丢掉我们唯一真正领先的东西。
