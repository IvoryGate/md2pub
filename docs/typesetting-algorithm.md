# 排版算法：从 Markdown 到一叠卡片

> 这篇文档讲实现，不讲参数审美。目标是把「为什么这行断在这里、为什么这一页空了一块」变成可解释、可复现的过程。

## 0. 管线总览

```text
Markdown
  → markdown-it token
  → IDM（与平台无关的 Block 列表）
  → 隐藏度量层（按卡片内容宽度真实渲染，逐块测高）
  → KP 断行（段内求最优行宽）
  → 分页（全篇 DP，决定每页装哪些行）
  → 卡片组装（段落/列表按行拆到多张卡）
  → 渲染 / 导出
```

关键原则是**测量与渲染同源**：度量层用的组件、字体、宽度、边距，与最终卡片完全一致。否则「测出来 1204 px，渲染出来 1210 px」就会溢出，且很难定位。

## 1. 测量：先把每个块的真实高度拿到

卡片排版不是「先分页再渲染」，而是「先渲染一遍，再决定怎么分」。度量层在屏幕外按原生尺寸渲染每一个块，然后读几何：

- 块高度 = `getBoundingClientRect().height` + 自身上下 margin；
- 标题、分隔线、图片记录 `topMargin`，当它落在页首时会被丢弃；
- 段落额外记录行高、拆分单元（`paraSplit`），供分页时按行拆；
- 列表记录每个条目的高度，供按条目拆；
- 图片、公式、Mermaid 异步撑高时，`ResizeObserver` 触发重测，直到高度稳定。

测量结果进入纯逻辑的 `paginateFlow`，这一步不碰 DOM。这样分页算法可以单独测试，也不会被浏览器布局时序干扰。

> 一个容易忽略的点：字体加载会改变行高。度量必须等 `document.fonts.ready`，否则首次测量用的是 fallback 字体的宽度，分页结果会在字体到位后整体错位。

## 2. 段内断行：KP 式全局最优

### 2.1 Token 化

一段中文不会被拆成「字」，而是拆成带排版属性的 token：

- 汉字：单字，通常是合法断点；
- 拉丁词 / 数字 / URL：整词，内部不拆（除非溢出兜底）；
- 标点：带 `canStart` / `canEnd` / `hangStart` / `hangEnd` 标记；
- 中西文交界：插入 1/4 em 的自动间隙（`gapAfter`），行首/行尾修剪。

### 2.2 禁则

一个断点 `j` 合法，当且仅当：

```text
tokens[j - 1].canEnd && tokens[j].canStart
```

闭合标点（`。，、；：？！）》」』】` 等）不能起行；起始标点（`（《「『【` 等）不能悬在行尾。这是硬约束，不参与代价权衡。

### 2.3 挤压池

全角标点自带约半个字的空白。KP 引擎把这些空白当作**可压缩的弹性**：

- 闭合标点的右空白：0.5 em；
- 起始标点的左空白：0.5 em；
- 两个标点相邻时，接触面共享，机会减半为 0.25 em。

一行可吸收的挤压量是这些机会之和。它把「行宽」从整字量子化变成近似连续，从而消掉中文行尾常见的大洞：差 8 px 放不下时，不必把整个词挪到下一行，挤一挤就过去了。

挤压只在**超宽**时使用（`d < 0`），并且每个机会不超过自己的上限。渲染时按同一套机会枚举分配位移，保证「算的时候扣了多少、画的时候就移多少」。

### 2.4 悬挂

行末闭合标点允许半个字宽溢出到页边距里，让墨迹与版心右缘齐平；行首起始标点同理，向左悬挂。这样既保持了「标点不孤立」的禁则，又不会在视觉上留下一个字的缺口。

### 2.5 DP：最小化整段松弛平方和

设一行的预算宽度为 `W`，实际内容宽为 `w`，定义松弛量：

$$
s = \frac{W - w}{em}
$$

代价是 `s²`。整段的断行方案是所有合法断点组合中，`Σ s²` 最小的那一个。用动态规划从段尾向前求：

```text
cost[n] = 0
cost[i] = min over j ( lineCost(i, j) + cost[j] )
```

`lineCost` 除了 `s²`，还有几层修正：

- 软阈值 0.38 em：超过后开始加罚，让「略有起伏」成为目标形态；
- 硬阈值 0.85 em：超过后重罚，避免明显空洞；
- 超过 0.55 em 的空洞再叠一次重罚——只要存在可行断点，就优先消灭大洞；
- 断点落在词内（`intra`）罚 10000，除非没有别的选择；
- 最后一行长度不作要求，但**必须装得下**：漏掉这条，DP 会把整段塞进末行，代价为 0，结果整段溢出。

如果所有方案都溢出，引擎会切到「允许溢出」模式重解一次：给溢出量一个高代价，而不是直接失败。这是极端长 URL / 不可断词的兜底。

> 为什么用平方而不是绝对值？平方会惩罚「一个特别大的洞」，倾向于把多余空间均摊到多行，形成均匀的呼吸感；绝对值则容易产生「一行很空、其他行很满」的解法。

## 3. 分页：把「行」装进「页」

段内断行解决一行放什么，分页解决一页放哪些行。

### 3.1 原子

分页把内容拆成不可再分的原子：

- 整块（标题、代码、公式、图、表格、引用）；
- 段落的一行（`line`）；
- 列表的一个条目（`item`）。

段落和列表可以跨页拆，但**标题、代码、公式、图、表格**是原子，不会被切开。原因是这些块切开后会失去语义完整性，读者看到半张表或半段代码，比看到一页留白更糟。

### 3.2 代价函数

对每一页，设内容高 `H`，已用高 `used`，行高 `lh`，留白代价为：

$$
\text{shortfall} = \left(\frac{H - used}{lh}\right)^2
$$

再加上几项硬/软约束：

| 项 | 值 | 作用 |
| --- | --- | --- |
| 孤行（orphan） | +0.6 | 段落首页只剩 1 行 |
| 寡行（widow） | +8.0 | 段落末页只剩 1 行 |
| 引导句悬尾 | +2.0 | 以「：」结尾的句子落在页尾 |
| 超大块 | +1000 | 单块本身超过一页 |
| 标题 keep-after | 硬约束 | 标题不能落在页尾 |

孤行的代价低，因为「一页开头只有一行」只是节奏问题；寡行的代价高，因为「翻页后只剩一行」会让读者觉得被耍了。

### 3.3 全篇 DP

设 `best[a]` 为从原子 `a` 开始排版的最小总代价：

```text
best[N] = 0
best[a] = min over b ( shortfall(used(a, b)) + extra(a, b) + best[b] )
```

其中 `b` 从 `a` 开始向后扩展，直到装不下为止。因为一页容量有限，内层循环的实际长度是「一页能装多少原子」，总复杂度近似 `O(N · K)`，`K` 是一页的平均原子数。

`best[0]` 就是全篇最优解；`next[]` 记录每个位置选择的页尾，最后回溯成页。

### 3.4 贪心模式

面板里可以切换到「顺序贪心」：能装就装，装不下就换页，不做全局优化。

它更快、更可预测，但会出现「前一页很空、后一页很满」的情况。保留这个模式，是因为有时作者希望分页结果稳定、可手算，而不是每改一个字就全篇重排。

### 3.5 拆分与续排

DP 决定「第 a 到 b 个原子放在这一页」，但段落行是虚拟的。度量层记录了每个段落每一行的 DOM Range，组装卡片时按行区间重新渲染：

- 第一页的段落带 `cont = false`，正常段首缩进/段距；
- 后续页的段落带 `cont = true`，去掉段首间距，直接续排；
- 列表同理，按条目区间续排，序号连续。

这就是「流式分页」：不是把整段搬来搬去，而是让内容像 LaTeX 一样自然流过页边界。

## 4. 与滚动同步的关系

编辑器和卡片是两套布局：同一段文字在编辑器里可能占 5 行，在卡片里可能占 8 行。用「行号比例」同步必然错位。

当前实现分两层：

1. **源码行**：每个块带 `line`，用于粗定位；
2. **文字锚点**：取可见区域第一段文字，归一化成 12 个字符（去掉标点、Markdown 标记），在另一侧搜索匹配。

编辑器侧用 CodeMirror 的 `scrollIntoView` 求精确目标，再退回原位做动画；卡片侧按 DOM 元素定位。快速滚动时，动画期间驱动侧的最新位置会进入队列，动画结束后补上最后一帧，避免「停下来还差一屏」。

## 5. 性能与边界

- **测量缓存**：`canvas.measureText` 的结果按「字体 + 字号 + 字距」缓存，字距变化会让缓存失效；
- **按文档缓存**：整篇归一化文本按不可变的 `Text` 对象缓存，编辑后自动失效；
- **异步块**：图片、Mermaid、KaTeX 撑高后会触发重测，分页在稳定后重算；
- **超长文档**：分页 DP 是 `O(N·K)`，但在几千个原子的量级仍然可交互；真正的主要成本是度量层的重排；
- **不可拆块**：表格、代码、图不跨页；如果单块高于一页，会给出溢出警告，而不是静默裁切。

## 6. 已知限制

- 拉丁文断词只做了整词保护，没有完整的 hyphenation 词典；
- 表格不支持横向拆分或跨页续表；
- 孤寡控制目前作用于段落与列表，标题的 keep-with-next 是硬约束；
- 分页代价函数是工程近似，不是 Knuth–Plass 的完整模型（没有 badness/penalty 的完整体系）；
- 字体子集按需加载，首次测量可能比后续慢。

这些限制不是「以后再说」，而是明确的取舍：在浏览器里、在可交互的时间预算内，优先保证**结果稳定、可解释、可回退**。当限制影响到真实排版时，再引入更重的算法，而不是一开始就把系统做成一个黑箱。

## 7. 一页纸总结

```text
段内：禁则 → 挤压池 → 悬挂 → min Σ slack²
页间：原子化 → min Σ shortfall² + 孤寡/引导句代价
拆分：段落按行、列表按条；标题/代码/图/表不可拆
同步：源码行 + 文字锚点；动画期间排队最后一帧
```

排版算法的目标不是「把内容塞满」，而是让每一页的留白都**看起来是故意的**。当读者注意不到分页的存在，算法就成功了。
