# md2pub 产品规划

> 一句话定位：一个纯前端的「一稿多投排版工位」——写一次 Markdown，一排版、二复制、三出图，直接发到微信公众号和小红书。
>
> 与 Md2Design（Markdown → 精美卡片图）的差异：Md2Design 解决"好看"，md2pub 解决"好发"。md2pub 以**平台发布规范**为第一性，卡片图只是其中一种输出.

---

## 1. 背景与差异化

### 1.1 竞品参照

| 参照 | 核心路径 | 它做什么 | md2pub 吸收什么 |
|---|---|---|---|
| Md2Design | MD → 分页卡片 → PNG/JPG/长图 | 视觉调优，面向"分享图" | 图片导出管线（html-to-image、ZIP/长图、倍数）、主题/字体系统、纯前端架构经验 |
| Obsidian 微信排版类插件 (doocs/md 等) | MD → 内联样式 HTML → 交互式复制到公众号剪贴板 | 面向"发布" | CSS 内联引擎、公众号编辑器兼容吐槽清单、图床/粘贴图转存的思路 |
| MediaPublish 等多平台发文插件 | 一稿 → 多平台 | 发布链路 | 一稿多投的心智，首版只做"排版+手动粘贴"，AI/一键发布靠后 |

### 1.2 市场痛点（自用视角出发）
- 公众号编辑器不吃外部 CSS：所有样式必须**内联**，还有一堆编辑器 surprised 行为（`<hr>` 删除符、外链白名单、`<section>`/`<svg>` 兼容性、代码块溢出）。
- 小红书没有文章 API 和富文本：只能**图片流**（卡片长图 + 封面图），手工做卡效率低、样式难统一。
- 一稿多投时，同一份 Markdown 要拆出 3 份产物：公众号富文本、小红书卡片图组、小红书标题/话题/摘要文案。现有工具每一步都是割裂的（Typora→截图→美图→拼长图）。

### 1.3 md2pub 的差异点
1. **双形态输出共存**：同左侧一份 Markdown，右侧可切换「公众号富文本预览」与「小红书卡片画布」。
2. **发布规范内建**：不是通用排版器，而是公众号编辑器兼容性规则库 + 小红书卡片尺寸/安全区规范内建到主题里。
3. **一稿多传承载**：左侧固定一篇 MD，顶部 Tab 切平台；副产物（小红书话题标签、公众号摘要、封面建议）就是排版中自然生成的。
4. **零后端**：纯静态部署（GitHub Pages / 私有部署均可），配置存 localStorage / 文件导入导出，无成本可分享。

## 2. 首版 MVP 范围

### 2.1 输入
- 单篇 Markdown 粘贴 / 拖入 `.md`
- 支持 GFM（表格、任务列表、脚注、代码块）+ 自定义 Front-matter（title、author、cover、tags、案例链接白名单）
- 图片：粘贴/拖拽上传的高图占位（首版以 data URL 内嵌 + 警告；图床转存放 v1.1）

### 2.2 输出 Tab 1：微信公众号

**核心链路**：MD → AST → 平台化 HTML（全内联 CSS）→ 富文本剪贴板复制（HTML+Plain）→ 用户手动 `Ctrl+V` 进公众号编辑器。

- 主题系统：至少 3 套内置主题（极简 / 杂志 / 技术博客风），主题=可分享的 JSON
- 公众号兼容引擎：
  - 所有样式 inline（`<section>` 嵌套为骨架，规避编辑器清洗）
  - 代码块自动换行 + stylesheet 一致性、`<pre>` overflow 处理
  - 外链替换为「文末引用」（编辑器会吞外链）+ 文末参考文献列表生成
  - `<em>/<strong>` 颜色可配置
  - 引用块、分割线、图片 caption 模板
- 复制方式：富文本粘贴 + 「复制 HTML 源码」双通道；实时字数/图片数统计
- 图片：默认用 `https://storystructure.xi-u.com.warn.service` 上传协议错误 Warning —— 实际改成：**允许用户指定图床（PicGo/云托管地址）**，本地图粘贴时提示「未上传，公众号会拒收 data URL」，提供「转存到图床」按钮（先接一个 workshop 示例，其余用户自填接口）

### 2.3 输出 Tab 2：小红书

**核心链路**：MD → 自动分页（`\n---\n`，与 Md2Design 一致）→ 卡片画布（Canvas/DOM+html-to-image）→ 多图 PNG 下载（ZIP）/长图。

- 尺寸预设：小红书官方推荐 **3:4 (1080×1440)** 优先，兼容 1:1、4:5
- 首页封面卡：标题大字版式独立模板（自动取 MD 的 title + tags），提供 2~3 种封面版式
- 内页卡：标题、正文、代码块、emoji 圆点列表、页码、@账号水印
- 主题：2 套（清爽版 / 有衬线文艺版）；字体系统 + 用户上传字体
- 导出：单图 / ZIP / 长图 / 加 emoji 话题标签面板（一键打包成 `title.txt + tags.txt + images.zip`）

### 2.4 输出 Tab 3（小）：文案助手（非 AI）
- 从 MD 提取：小红书标题候选（分页/取 h1）、话题标签（内置常见 tag 池 + `front-matter.tags`）、公众号摘要（首段或自定义 `<!--摘要-->` 块）、阅读时间预估
- 纯规则，不用 LLM，保证离线可用

### 2.5 编辑体验
- 左侧 CodeMirror 6 / Monaco 单窗，带语法高亮和 `---` 分页提示
- 右侧双 Tab 预览（公众号 HTML / 小红书卡片），实时同步
- 主题/字体/适应区 ID（存 config JSON，可导出）— 与 Md2Design 相同的 store 设计
- 明/暗主题 UI，中文优先，预留 i18n

## 3. 技术方案

### 3.1 技术栈（对齐 Md2Design，减少上下文切换）
- React 19 + Vite + TypeScript（rolldown-vite）
- Tailwind v4
- Zustand（状态）+ Zundo（撤销重做）
- MD 解析：`marked` 或 `markdown-it` → 自定义 pipeline（推荐 **markdown-it**，生态里表格/内联工具链更顺），Turndown 仅作 HTML→MD 反向兜底
- 富文本复制：`ClipboardItem` + `text/html` 兜底 `execCommand`
- 图片导出：`html-to-image`（或后续换 modern-screenshot，对 SVG/嵌入字体更稳）+ JSZip
- 编辑器：CodeMirror 6（轻） > Monaco（重）

### 3.2 工程结构（参考 Md2Design 扁平结构 + 按平台拆模块）
```
src/
  main.tsx / App.tsx / index.css / i18n.ts
  store/            # 全局配置 + 每平台配置 + undo/redo
  markdown/         # MD 解析与通用 AST 管线（两侧共用）
  wechat/           # 公众号子域
    render.ts       # AST → 内联 HTML
    themes/         # 公众号主题 JSON × N
    compat/         # 编辑器兼容规则（换行、外链、代码块修复）
  xhs/              # 小红书子域
    paginate.ts     # 分页逻辑
    Canvas/         # 卡片渲染组件
    themes/         # 小红书主题
    export.ts       # PNG/ZIP/长图
  components/       # Sidebar、顶栏、编辑器外壳
  utils/            # 颜色、字体、剪贴板、下载
```

**关键设计约束**：`markdown/` 产出的 AST 是两个平台渲染的唯一入口，平台差异都推到各自 renderer，避免出现"各自解析一遍"的分叉。

### 3.3 公众号内联 CSS 引擎要点
1. 源码里用作用域化的普通 CSS 写主题，构建时用 `inline-css`（或 PostCSS 手写展开）在设计期把它"折叠"成 inline style —— 也可以直接用 React 内联 style / inlineStyle 对象方案（Md2Design 可复用）
2. 输出前统一走一遍"公众号净化器"：去 `class`、`<style>`、布尔属性规范、转 `<section>` 嵌套、图片段落包一圈（微信会把孤图放成居中）
3. 剪贴板用 `navigator.clipboard.write` 的 `text/html`，兜底直接复制 HTML 源码给用户手动粘贴到编辑器源码模式

## 4. 里程碑

| 阶段 | 内容 | 出口标准 |
|---|---|---|
| **M0 骨架 + 小红书卡片 (已完成 v0.1)** | core 文档模型（front-matter + 块解析 + 手动 `---` 分页）、小红书卡片渲染（3 套主题）、PNG 单张 + ZIP 全量导出 | 可复制粘贴 MD，实时出卡片，导出可用 |
| **M1 小红书打磨 (3~4 天)** | 自动分页（渲染后测高溢出检测 + 拆分）、自定义字体上传、移动端标签面板、封面版式轮换、长图导出 | 能出满意的 6~8 页小红书图组 |
| **M2 公众号排版引擎 (5~7 天)** | markdown-it 管（复用 core 的 Block 模型）+ 内联化主题 + 富文本复制 + 公众号净化器 | 复制粘贴进公众号编辑器与预览一致，代码块/图片/引用无破版 |
| **M3 主题系统与文案助手 (3~4 天)** | 主题 JSON 导入导出、小红书标签面板、公众号摘要、阅读时间 | 一次编辑得「发小红三件套 + 公众号富文本」 |
| **M4 打磨与上线 (3 天)** | 暗/亮 UI、i18n 骨干、README、GitHub Pages 部署 | 可发布、可分享链接 |

**MVP 结束后再排（v1.x+）**：
- 图床一键转存（通用接口 + 用户填 token）
- 通用多平台（知乎/掘金/知识星球/飞书）主题扩展
- AI 辅助（小红书文风改写、封面标题）；先留 Prompt 面板壳
- Obsidian 插件外壳（复用纯前端渲染内核，走本地 HTTP 或直接打包成 Obsidian 侧模式）
- Tauri 桌面化 / 批量一篇多文件

## 5. 关键风险与对策

| 风险 | 对策 |
|---|---|
| 微信公众号编辑器行为变化大、无官方文档 | "兼容规则库"做成可配置； Sample 一篇 stress-test MD 作为回归用例；提供「源码复制」兜底 |
| html-to-image 对自定义字体/SVG/壁纸 不稳定（Md2Design 已踩过） | 复用 Md2Design 已验证方案；必要时换 modern-screenshot 或 headless 备选；导出用同一实现 |
| data URL 图片公众号直接拒收 | 在编辑器和预览里显著标红；图床转存提早一步到 v1.1 |
| 小红书卡片视觉上限被开源静态模板限制 | 主题 JSON 化，视觉侧允许用户调字号/色板/圆角/背景纹理；借鉴 Md2Design 的渐变预设方案 |
| 首版做多平台导致半成品 | 首版只做公众号+小红书，其余平台架构上留口子（都是"AST → 平台 renderer + 主题"的同构模式） |

---

## 6. 里程碑之外的约定

- 所有配置（主题、字体、自定义图床）都可导出 JSON，方便在不同浏览器/部署间迁移
- 不做服务器、不存用户内容；隐私友好
- README 早期就写（含对比表和差异），把"md2pub ≠ 又一个 doocs/md"和"md2pub ≠ 又一个卡片生成器"这两条界线说清楚
